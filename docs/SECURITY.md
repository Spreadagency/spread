# الأمان وسلامة البيانات — قايمة الفحص + «لو التقرير قال كذا تعمل إيه» (MCP المرحلة 8)

كل حاجة هنا ظاهرة في الأدمن ← **AI CENTER ← الأمان** (`admin/ai-security.php`)، وClaude بيقراها في المراجعة اليومية.

| التبويب | جاي منين | بيتحدّث إمتى |
|---|---|---|
| **نظرة عامة** | 16 فحص إعدادات على الموقع نفسه (`includes/security-center.php`) | كل يوم قبل التقرير اليومي بساعة · أو زرار «افحص دلوقتي» |
| **سلامة البيانات** | 12 فحص ترابط (قراءة بس — مابيصلّحش لوحده) | نفس الميعاد |
| **ملاحظات الأمان** | الإعدادات + OWASP ZAP + npm audit + اللي Claude بيلاقيه | يومي (الإعدادات) · أسبوعي من الـ VPS (ZAP و npm) |
| **السجلات** | محاولات دخول فاشلة · رفض الـ Internal API · أخطاء | لحظي |
| **اختبارات الموقع** | Playwright (كل صفحات العميل والأدمن) | أسبوعي من الـ VPS · أو يدوي |

**القواعد:**
- الفحص **مابيغيّرش بيانات** أبدًا. بيسجّل بس في قاعدة الـ AI.
- الفحوصات بتتجاب من غير الأسرار نفسها. مثلًا بيقول «التوكن قصير»، مش بيعرض التوكن.
- لو فيه مشكلة **حرجة**، بيوصل تنبيه أحمر في جرس الأدمن (مرة واحدة في اليوم).
- المشكلة اللي اتصلّحت بتتعلّم «اتصلّحت» لوحدها في الفحص اللي بعده.
- اللي علّمته «مقبولة» أو «إنذار كاذب» بيفضل زي ما هو.

## 1) قايمة الفحص قبل التشغيل الحقيقي

علّم على كل واحدة. كلها لازم ✅ في «نظرة عامة» قبل ما تفتح للعملاء:

- [ ] **حرجة:** توكن الـ Internal API (48+ حرف) · مفتاح التشفير · مجلد الرفع مايشغّلش PHP · مفيش أدمن بباسورد سهل.
- [ ] **عالية:** `APP_DEBUG=false` · HTTPS · سر الـ cron (24+ حرف) · الـ Internal API مقفول على IP الـ VPS · مستخدمين MySQL محدودين للـ MCP · إيصالات الدفع مقفولة · صلاحيات `config.php` (640 أو 644).
- [ ] **متوسطة:** `display_errors=Off` · PHP 8.1+ · كوكي الجلسة HttpOnly · كل الترحيلات اتشغّلت · الـ cron شغال.
- [ ] نسخة احتياطية يومية للقاعدتين (cPanel ← Backup، أو JetBackup).
- [ ] `includes/config.php` و`.env` بتاع الـ VPS **مش** على GitHub ولا في أي zip اتبعت لحد.
- [ ] تحقق بخطوتين (2FA) على: cPanel · GitHub · مزوّد الـ VPS · إيميل الأدمن.
- [ ] حسابات الأدمن: كل واحد بصلاحياته بس (الأدمن ← الأدمنز ← الأدوار). مفيش حساب مشترك.
- [ ] اختبار الموقع (Playwright) عدّى 100% على staging.
- [ ] ZAP baseline مفيهوش **High**.

## 2) «لو التقرير قال كذا تعمل إيه»

### إعدادات الموقع (تبويب نظرة عامة)
الحل مكتوب جنب كل نقطة في الصفحة. هنا اللي محتاج شرح زيادة:

| النقطة | الخطورة | تعمل إيه |
|---|---|---|
| **توكن الـ Internal API ضعيف** | حرجة | `openssl rand -hex 32` ← حطه في `INTERNAL_API_TOKEN` في `config.php` **و** في `.env` على الـ VPS ← `sudo systemctl restart spread-mcp`. لازم الاتنين نفس القيمة |
| **مفتاح التشفير ناقص** | حرجة | ⚠️ **ماتغيّروش** لو كان موجود وفيه مفاتيح API متخزّنة بيه، لأنها هتبوظ. لو ناقص خالص: 64 حرف عشوائي في `ENCRYPTION_KEY`، وبعدين دخّل مفاتيح الـ API تاني |
| **مجلد الرفع بيشغّل PHP** | حرجة | ارفع `storage/uploads/.htaccess` من الحزمة. ولو حد رفع ملف `.php` هناك، امسحه وراجع «السجلات» |
| **أدمن بباسورد سهل** | حرجة | غيّره فورًا. ولو الحساب ده مش محتاجه، اقفله |
| **الـ Internal API مفتوح لأي IP** | عالية | `define('INTERNAL_API_IPS', 'IP_الـVPS');` |
| **مستخدمين MySQL للـ MCP مش محدودين** | عالية | الأدمن ← إعداد الـ MCP ← «مستخدمين MySQL» (الخطوات في `sql/2026_mcp_db_users.example.sql`) |
| **الـ cron واقف** | متوسطة | cPanel ← Cron Jobs. الأمر موجود في «فحص التحديث». من غيره المحرك والنشر والتقرير اليومي والفحص ده نفسه مش هيشتغلوا |

### سلامة البيانات (تبويب سلامة البيانات)
كل مشكلة فيها **العدد** و**أرقام السجلات (IDs)**. الفحص مابيصلّحش لوحده عن قصد، لأن أغلبها فلوس أو كريدت ولازم بني آدم يراجع.

| المشكلة | الخطورة | تعمل إيه |
|---|---|---|
| **رصيد بالسالب** | عالية | افتح العميل ← سجل الكريدت. غالبًا خصم اتكرر أو استرداد ماحصلش. صلّحه بتعديل يدوي من صفحة العميل مع سبب واضح |
| **دفع اتعتمد من غير باقة** | عالية | افتح طلب الدفع. لو الكريدت اتضاف والباقة لأ، ابدأ دورة للعميل من صفحته |
| **فيديو اتدفع ومااتبعتش** | عالية | «طلبات الفيديو» ← «اتبعت للتنفيذ». ابعت للعميل إن الطلب في الطريق |
| **كريدت محجوز لشغل خلص** | عالية | ده bug. سجّله في «طلبات التعديل» بالأرقام، أو ابعته للمطوّر. ماتمسحش الحجز بإيدك من القاعدة |
| **أكتر من باقة شغالة** | متوسطة | الأحدث هو اللي بيتحسب. راجع إن الأقدم بقى «replaced» |
| **شغل واقف أكتر من ساعتين** | متوسطة | اتأكد إن الـ cron شغال. الشغلانة بتكمّل أو بتفشل والحجز بيرجع |
| **منشورات واقفة في «بيتنشر»** | متوسطة | غالبًا توكن الصفحة انتهى. العميل يربط الصفحة تاني |
| **مهام وكيل واقفة** | متوسطة | «المساعدين» ← سجل المهمة ← إلغاء، والعميل يبدأ تاني (الكريدت المحجوز بيرجع) |
| **أكتر من إصدار برومبت مفعّل** | متوسطة | «البرومبتات» ← فعّل الإصدار الصح تاني (التفعيل بيقفل الباقي) |
| **دفع مستني أكتر من 3 أيام** | متوسطة | «المدفوعات» ← اعتمد أو ارفض مع سبب |
| **تصميمات / منشورات يتيمة** | منخفضة | مش ظاهرة لحد. سيبها للتنظيف الدوري |

> لو المشكلة طبيعية عندك (مثلًا عميل اتفقت معاه على رصيد سالب)، دوس **تجاهل**، ومش هتظهر تاني لحد ما تدوس «افتح تاني».

### OWASP ZAP (ملاحظات الأمان ← المصدر zap)
| التحذير | تعمل إيه |
|---|---|
| **Content Security Policy (CSP) Header Not Set** | ابدأ بـ `Content-Security-Policy-Report-Only` في `.htaccess` أسبوع، وبعدين فعّلها. ماتفعّلهاش مرة واحدة، علشان ممكن تقفل سكريبتات |
| **Missing Anti-clickjacking Header** | `Header always set X-Frame-Options "SAMEORIGIN"` في `.htaccess` |
| **X-Content-Type-Options Header Missing** | `Header always set X-Content-Type-Options "nosniff"` |
| **Strict-Transport-Security Header Not Set** | بعد ما تتأكد إن HTTPS شغال على كل حاجة: `Header always set Strict-Transport-Security "max-age=31536000"` |
| **Cookie No HttpOnly / Secure / SameSite** | `session_set_cookie_params` في `config.php` (شوف نقطة «كوكي الجلسة») |
| **Server Leaks Version Information** | cPanel ← Apache: `ServerTokens Prod`، وPHP: `expose_php = Off` |
| **Information Disclosure — Debug Error Messages** | `APP_DEBUG=false` و `display_errors=Off` |
| **أي حاجة High** | علّمها «بنشتغل عليها»، وابعتها لـ Claude: «حلّل ملاحظة الأمان رقم X واقترح تعديل». هيعمل **اقتراح تعديل** يستنى موافقتك |

### npm audit (ملاحظات الأمان ← المصدر dependency)
| الحالة | تعمل إيه |
|---|---|
| فيه تحديث | على الجهاز اللي فيه الكود: `cd mcp-server && npm audit fix && npm run build`، وبعدين حزمة جديدة ← `install.sh update` |
| مفيش تحديث | اقرا التحذير: لو في جزء مش مستخدم، علّمها «مقبولة» واكتب السبب |
| **معروفة ومقبولة:** `@hono/node-server` (متوسطة) | في `serveStatic`، وخادمنا مابيقدّمش ملفات ثابتة. جاية من جوه `@modelcontextprotocol/node`. بتتقفل لوحدها لما المكتبة تتحدث |

### اختبارات الموقع (Playwright)
| النتيجة | تعمل إيه |
|---|---|
| `HTTP 500` | افتح الصفحة بنفسك ← cPanel ← Errors (أو `error_log`) |
| `خطأ PHP ظاهر في الصفحة` | نفس اللي فوق، وكمان `display_errors` مفتوح (صلّحه) |
| `JS: …` | خطأ JavaScript. افتح الصفحة ← F12 ← Console |
| `سكرول أفقي على الموبايل` | عنصر أعرض من الشاشة. ابعت الصفحة لـ Claude أو للمطوّر |
| `الدخول فشل` | حساب الاختبار اتقفل أو الباسورد اتغير. حدّثه في `/opt/spread-mcp/checks.env` |

### السجلات
| اللي بتشوفه | تعمل إيه |
|---|---|
| محاولات دخول فاشلة كتير من IP واحد | الموقع بيقفل بعد محاولات. لو مستمرة: cPanel ← IP Blocker |
| رفض Internal API (`ip_denied`) من IP غريب | حد عارف العنوان. مش هيعدّي من غير IP + توكن. لو التوكن ممكن يكون اتسرّب، غيّره (فوق) |
| رفض بـ `auth` من IP الـ VPS | التوكنين مش زي بعض |

## 3) لو حصل اختراق أو شك في اختراق

1. **اقفل Claude فورًا** (من الـ VPS):
   ```bash
   sudo systemctl stop spread-mcp && cd /opt/spread-mcp/app && sudo -u spreadmcp npm run revoke-all
   ```
   ومن الأدمن ← إعدادات الجودة ← اقفل كل الأدوات.
2. **غيّر الأسرار**: `INTERNAL_API_TOKEN` (في المكانين) · سر الـ cron · باسوردات الأدمن · باسورد صاحب الموقع للـ MCP · باسورد MySQL من cPanel وحدّث `config.php`.
3. **ماتمسحش حاجة.** خد نسخة احتياطية كاملة الأول (ملفات + القاعدتين)، علشان تعرف إيه اللي حصل.
4. راجع: «السجلات» · «سجل الـ MCP» · سجل نشاط الأدمن · cPanel ← Raw Access Logs.
5. دوّر على ملفات `.php` في `storage/uploads/` أو ملفات اتعدّلت قريب: cPanel ← File Manager ← ترتيب بالتاريخ.
6. لما تخلص: شغّل الخادم تاني، واربط Claude من جديد، وافحص («افحص دلوقتي» + ZAP + اختبار الموقع).

## 4) Claude بيعمل إيه في الأمان (والممنوع عليه)

- **بيقرا:** فحص الإعدادات · سلامة البيانات · السجلات · نتايج ZAP و npm و E2E (`spread_security_scan` · `spread_integrity_check` · `spread_get_security_logs` · `spread_get_e2e_results` · `spread_dependency_audit`).
- **بيسجّل:** ملاحظة أمان أو مشكلة ترابط (`spread_save_security_finding` · `spread_save_integrity_issue`)، في قاعدة الـ AI بس.
- **بيقترح:** تعديل (`spread_propose_change`). بيستنى موافقتك في «الاقتراحات».
- **ممنوع:** يحذف أي حاجة · يلمس الكريدت أو الدفع أو الاشتراكات أو الحسابات أو الباسوردات أو رصيد الأفلييت · يغيّر إعدادات الموقع · يصلّح بيانات بنفسه.
